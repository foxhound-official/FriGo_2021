# FriGo

Android-приложение для управления домашними продуктами, рецептами и сроками годности.

FriGo объединяет локальный аккаунт пользователя, список продуктов с разделением на холодильник и морозилку, информацию о сроках хранения и раздел с рецептами. Проект содержит собственный пользовательский интерфейс, анимации, локальную SQLite-базу и набор справочных данных о продуктах.

`FriGo_2021` представляет собой более развитую версию раннего прототипа FriGo. Основная структура приложения уже реализована, однако часть данных и функций остаётся демонстрационной и не полностью подключена к постоянному хранилищу.

## Возможности

В приложении предусмотрены:

* регистрация локального аккаунта;
* авторизация;
* сохранение текущей сессии;
* отображение имени и данных пользователя;
* изменение данных аккаунта;
* удаление локальных данных приложения;
* список продуктов;
* разделение продуктов между холодильником и морозилкой;
* поиск по списку продуктов;
* добавление продукта через интерфейс;
* выбор существующего типа продукта или создание собственного;
* список рецептов;
* переход на внешние сайты с рецептами;
* список сроков годности;
* экран настроек;
* русская и английская локализация ресурсов;
* собственные анимации интерфейса;
* собственный шрифт Comfortaa;
* локальная SQLite-база.

Главное меню предоставляет доступ к четырём направлениям:

```text
FriGo
 |

 |    +-- Холодильник
 |    +-- Морозилка
 |    +-- Поиск
 |    +-- Добавление продукта

 |    +-- Внешние сайты с рецептами
```

Пункт «Облако» присутствует в интерфейсе приложения, однако отдельная система серверной синхронизации в просмотренном коде не реализована.

## Работа с продуктами

Основной функциональный экран приложения находится в `GroceryActivity`.

Пользователь может переключаться между:

* холодильником;
* морозилкой.

Для списка используется `RecyclerView` с собственным адаптером.

Также предусмотрены:

* поиск по продуктам;
* кнопка добавления;
* выбор существующего типа продукта;
* ввод собственного типа;
* ввод собственного названия;
* отдельные состояния интерфейса для холодильника и морозилки;
* анимации появления и скрытия карточек.

Форма добавления поддерживает два сценария:

```text
Добавление продукта
       |
       +-- Существующий продукт
       |      |
       |      +-- Тип
       |      +-- Название
       |
       +-- Пользовательский продукт
              |
              +-- Собственный тип
              +-- Собственное название
```

Интерфейс предусматривает отдельные элементы для количества, срока хранения и дополнительной информации, а структура SQLite также содержит соответствующие поля.

При этом текущая реализация `GroceryActivity` не завершает полноценное сохранение добавленного продукта в базу данных. Поэтому экран следует рассматривать как реализованный UI и прототип механики управления продуктами, а не как полностью завершённый CRUD-модуль.

## Локальная база данных

FriGo использует SQLite через стандартный Android API.

База называется:

```text
data.db
```

При первом запуске `SplashActivity` создаёт основные таблицы приложения.

### Users

Хранит локальные аккаунты:

```sql
Users (
    Login TEXT PRIMARY KEY,
    Pass TEXT,
    Name TEXT,
    Sex INTEGER
)
```

В процессе регистрации также используется вариант структуры с дополнительным `ID_USER`.

### Fridge

Хранит продукты холодильника:

```sql
Fridge (
    ID_FOOD INTEGER PRIMARY KEY AUTOINCREMENT,
    Login TEXT,
    ID_PRODUCT INTEGER,
    Count INTEGER,
    ShelfData DATETIME,
    AddInfo TEXT
)
```

### Freezer

Хранит продукты морозилки:

```sql
Freezer (
    ID_FOOD INTEGER PRIMARY KEY AUTOINCREMENT,
    Login TEXT,
    ID_PRODUCT INTEGER,
    Count INTEGER,
    AddInfo TEXT
)
```

### Dict_product

Справочник продуктов:

```sql
Dict_product (
    ID_PRODUCT INTEGER PRIMARY KEY AUTOINCREMENT,
    Type TEXT,
    Name TEXT
)
```

При первоначальной инициализации приложение пытается заполнить справочник данными из assets.

## Регистрация и авторизация

Регистрация реализована в `RegistrationActivity`.

Пользователь указывает:

* логин;
* пароль;
* повтор пароля;
* имя;
* пол.

Приложение проверяет:

* обязательность основных полей;
* минимальную длину логина;
* отсутствие пробелов в логине;
* минимальную длину пароля;
* совпадение паролей;
* отсутствие уже существующего логина.

После регистрации данные записываются в SQLite, а информация о текущем пользователе сохраняется через `SharedPreferences`.

Авторизация реализована в `LoginActivity`.

При успешном входе приложение сохраняет:

```text
LOGIN
NAME
SEX
ACCOUNT_LOGGED
```

в `SharedPreferences` и открывает главное меню.

## Сессия пользователя

Для хранения состояния текущей сессии используется:

```text
SharedPreferences
```

Основные значения:

```text
user_data
 |
 +-- LOGIN
 +-- NAME
 +-- SEX
 +-- ACCOUNT_LOGGED
 +-- DATABASE_LOADED
```

При запуске `SplashActivity` проверяет состояние пользователя и базы данных.

Если аккаунт уже отмечен как авторизованный, приложение пропускает обычный сценарий входа и переводит пользователя в главное меню через `LoginActivity`.

## Главное меню

`MenuActivity` отображает данные текущего пользователя.

Если пользователь указал имя, оно используется вместо логина.

Также в зависимости от сохранённого значения `SEX` выбирается соответствующая иконка:

```text
0 -> мужчина
1 -> женщина
2 -> не указано
```

Из меню доступны основные разделы приложения:

* продукты;
* рецепты;
* срок годности;
* облако;
* настройки.

## Рецепты

Раздел реализован в `RecipeActivity`.

Он содержит два режима:

```text
Рецепты
 |
 +-- Сайты с рецептами
 |
 +-- Продукты
```

Для списка продуктов используется `RecyclerView`.

В проекте присутствует демонстрационный набор продуктов, например:

* говядина;
* пшеничная каша;
* мороженое;
* спаржа;
* молоко;
* морковь;
* капуста;
* кефир;
* яйца;
* сыр;
* соевый соус;
* майонез;
* мёд.

Также предусмотрены переходы на внешние сайты с рецептами.

## Срок годности

Раздел реализован в `ShelfLifeActivity`.

Для отображения используется `RecyclerView` и собственный `ShelfLifeStateAdapter`.

В текущей версии в коде находится демонстрационный набор данных:

```text
Молоко          Кисломолочное   12.07.2021   7 дней
Творог          Кисломолочное   16.07.2021   11 дней
Яйца куриные    Другое          11.07.2021   6 дней
Огурцы          Овощи           12.08.2021   37 дней
Мясо говядина   Мясное          01.08.2021   26 дней
```

Эти значения создаются непосредственно в `ShelfLifeActivity`, поэтому экран не получает их из таблиц `Fridge` или `Freezer`.

## Настройки

`SettingsActivity` содержит несколько разделов:

* настройки приложения;
* аккаунт;
* информация.

В разделе аккаунта отображаются:

* логин;
* имя;
* выбранный вариант пола.

Пользователь также может изменить имя и значение пола после подтверждения текущим паролем.

Отдельная функция позволяет полностью сбросить локальное состояние приложения:

```text
data.db
SharedPreferences
```

после чего приложение возвращается к первоначальному состоянию.

Также предусмотрена функция отправки отчёта разработчику через системный почтовый клиент.

## Справочные данные

В `app/src/main/assets` находятся дополнительные файлы:

```text
comfortaa_light.ttf
products_names.docx
products_types.docx
```

Шрифт используется для оформления интерфейса.

Документы содержат вспомогательные данные, связанные со справочником продуктов.

В коде первоначальной инициализации базы используется файл:

```text
products_names.txt
```

поэтому между текущим кодом и фактическим содержимым assets есть несоответствие. Для корректной первоначальной загрузки базы этот файл должен присутствовать в APK либо код должен быть приведён в соответствие с фактическим форматом ресурсов.

## Технические ограничения

Проект является исторической версией Android-приложения и использует устаревший на сегодняшний день toolchain:

```text
Gradle 6.5
Android Gradle Plugin 4.1.2
compileSdkVersion 30
targetSdkVersion 30
Java 8
```

Также в проекте есть несколько важных технических ограничений.

Пароли пользователей сохраняются в SQLite в открытом виде. Для production-приложения такой подход требует замены на безопасное хранение и соответствующую схему аутентификации.

SQL-запросы во многих местах формируются конкатенацией пользовательского ввода. Это создаёт проблемы с экранированием данных и потенциальные SQL-инъекции. Для нормальной реализации следует использовать параметризованные запросы или более современный слой хранения данных.

Некоторые структуры базы создаются с различающимся набором полей в разных `Activity`. Это указывает на то, что схема БД развивалась вместе с проектом и не была вынесена в единый слой управления схемой.

Часть данных в интерфейсе является демонстрационной. В частности, список сроков годности и список продуктов для раздела рецептов создаются непосредственно в Java-коде.

Пункт синхронизации с облаком присутствует в интерфейсе, однако полноценного backend или сетевого механизма синхронизации в просмотренной реализации нет.

В `AndroidManifest.xml` присутствуют разрешения, связанные с аккаунтами и контактами, а также доступом к интернету. Часть логики работы с контактами и `AccountManager` в `LoginActivity` закомментирована.

## Статус

Проект сохранён как историческая версия FriGo от 2021 года.

Основные экраны приложения реализованы, локальная база данных и аккаунты работают на уровне прототипа, а интерфейс управления продуктами содержит значительную часть необходимой механики.

При этом полноценное хранение всех пользовательских данных, облачная синхронизация и некоторые связанные с продуктами функции не доведены до завершённой production-реализации.
